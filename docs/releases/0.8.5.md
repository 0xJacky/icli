- `app frontmost` no longer names a view service SpringBoard hosts in its own interface. On an iPad's Home Screen it answered `com.apple.DocumentManager.DockFolderViewService`, the Dock's folder stack, which holds the same FrontBoard focus assertion as an app on screen; `app launch` then waited for an app that was already in front. Apps tagged hidden are left out, and when several apps hold the assertion, as with windows side by side in iOS 27, the one FrontBoard gives the foreground-focal priority is the frontmost. Tested on an iOS 27.0.1 iPad and an iOS 26.6.2 iPhone (vphones with RootHide) and an iPhone SE with iOS 15.8.6 (Dopamine, rootless).
- The acceptance TestHost launches on iOS 27. UIKit in iOS 27 stops an app built with that SDK at launch unless it uses the scene life cycle (the `UIKit/assert_for_no_scene_lifecycle` feature flag; iOS 26 only logs), so every case that opened TestHost failed with `app did not become frontmost`. TestHost and the install fixtures made from it now declare a scene manifest and use a scene delegate.
